Reports

Review a project

Dashboard

See the configured projects, their GitLog rows, stored report count, latest run, and Change from baseline (%) chart. Each chart shows Total function complexity and Mean complexity per function relative to the earliest saved run. Sync GitLog to import matching commits, or generate reports for one project or all projects.

Project reports

Choose a project to view its saved runs and the same two baseline trends as the dashboard. Use the range sliders to narrow the period; the first displayed run becomes the baseline. Positive percentages mean an increase, negative percentages mean a decrease, and the zero line marks the baseline value. Temporary runs are excluded from these charts.

Complexity analysis

Open Complexity analysis from a project report to reach the Project analysis dashboard. It links to Scope and hotspots, Baseline changes, Change Attribution, Persistent Hotspots, Complexity Distribution, Complexity Concentration, and Module Trends. Choose the report that answers your question using the explanations below.

Run summary

Open a stored run to inspect every included file. Sort by any metric column, filter Complexity, Functions, Complexity Total, or Complexity Average with minimum and maximum values, and select View functions to inspect a file's function entries. Table filters only change the rows shown; they do not change report metrics.

File exclusions

Add or remove project-specific exact paths or path patterns. Use % as a wildcard. Saved exclusions are persisted in config.json and immediately change visible dashboard, report, summary, and comparison metrics; original report data remains stored.

Current local code

Generate a temporary report to analyze the current local code rather than a historical commit. It appears separately from saved runs and replaces the previous temporary report for that project. Analysis reports exclude temporary runs by default; select Include temporary reports to add them to an analysis.

Project analysis

Choose an analysis report

Scope and hotspots

Review historical file-level metrics for the whole project or selected files over a date range. Toggle metrics and use the hotspot table to compare each file's latest complexity, change, peak, and number of reports containing it.

Use this report to locate files worth investigating. Its legacy file-complexity totals count repeated function names once; the function-based reports below count every function entry.

Baseline changes

Choose a fixed baseline run and date range to compare function counts, total function complexity, mean complexity, the 90th percentile, and the high-complexity function rate. Unlike the simplified project chart, changing the date range does not change the selected baseline.

The percentage chart measures relative change. Complexity per function shows the raw mean and 90th percentile, while the high-complexity chart shows the percentage above your threshold, default 10. The history table includes raw values and baseline differences. Rate differences use percentage points: a rise from 10% to 12% is +2 pp.

Change Attribution

Explain the net change in total function complexity between the first and last selected runs. Contributions from added, removed, name-matched, and unmatched functions sum to the overall difference. Positive contributions add complexity; negative contributions remove it.

Functions are matched only when a file path and function name uniquely identify an entry in both runs. Renames and moves appear as additions/removals; duplicate names remain unmatched. A name-based match is an inference, not a verified function identity.

Persistent Hotspots

Find files that repeatedly contain at least one function strictly above the selected complexity threshold. Persistence is hotspot runs divided by runs containing the file. Period coverage is runs containing the file divided by all selected runs.

Read both percentages together: a file present in only one run can have 100% persistence but low coverage. Latest metrics are N/A when the file is absent from the last run. Renamed paths are treated as different files.

Complexity Distribution

Compare function counts and percentages in the 1-5, 6-10, 11-20, and 21+ complexity bands across the selected period. Use the percentages to see whether the mix is shifting toward simpler or more complex functions, and the counts to see changes in project size.

These score bands are fixed, unlike the configurable threshold used by hotspot and high-complexity-rate reports. Percentages are N/A for runs without functions.

Complexity Concentration

Measure how much of the total function complexity belongs to the most complex percentage of functions, default 10%. A large share means complexity is concentrated in a relatively small set of functions. The last run's ranked-function table identifies that set and shows its cumulative share.

The selected count rounds up to whole functions, so the actual selected percentage can exceed the requested value, especially in small projects. Equal-score ties are ordered by file path and line.

Module Trends

Group files by their first directory levels, default 3, to compare parts of the project. Select modules and a metric: mean function complexity, high-complexity function rate, function count, or total function complexity. Root-level files form the (root) group.

The table compares each module's mean in the first and last selected runs and shows how many runs contain it. Missing-module means are N/A, not zero. Directory depth changes the grouping; these modules are path groups, not inferred architectural boundaries.

Reading historical changes Function-based analysis uses individual stored function scores after the same built-in and project-specific exclusions. First/last run selectors define the period for the five additional reports; their tables support searching, sorting, and page-size selection. Growth, deletions, and changing scope can affect trends, so a lower total alone does not prove that existing functions became simpler. These reports do not measure Git change frequency.

Comparisons

Compare two stored runs

Select runs

From a project's Compare section, select any two stored runs. The older timestamp is treated as the first run and the newer timestamp as the second run, regardless of selection order.

Read the result

Rows are matched by file path. The values in parentheses are the first and second run when they differ. A green row is a file added in the second run; a red row is a file that existed only in the first run.

Changes

For files in both runs, Complexity Change is second-run Complexity minus first-run Complexity. Average Change uses the same subtraction for Complexity Average. A plus sign means the value increased.

Scope

The same built-in and project-specific exclusions apply to comparisons. Excluded files do not appear and do not affect visible report-level statistics.

Calculations

How complexity values are computed

Function Complexity

The cyclomatic complexity reported for a function. The report uses ESLint's complexity result when available. Its fallback starts at 1 and adds the function's control-flow, expression, and default-parameter decision points.

Functions

The number of function entries found in the file.

Complexity

The file's stored complexity: the sum of its function complexities. When an imported function report has repeated function names in one file, this value counts each name once to retain the original report behavior.

Complexity Total

The sum of all function-entry complexities in the file, including repeated function names.

Complexity Average

File Complexity divided by Functions. A file with no functions has an average of 0.

Report Total Complexity

The sum of the included files' stored Complexity values.

Report Average Complexity

Report Total Complexity divided by the number of included files. It is an average per file, not an average of the file averages. A report with no included files has an average of 0.

Report Average Complexity Per Function

Report Total Complexity divided by the total number of included functions. A report with no included functions has an average of 0. This legacy value can differ from the analysis reports' mean because Report Total Complexity deduplicates repeated function names.

Total function complexity

The sum of every included function entry's complexity, including repeated names. This is the total used by function-based analysis and the simplified baseline charts.

Mean complexity per function

Total function complexity divided by the included function count. This arithmetic mean measures typical function complexity rather than project size. It is N/A when no function data is available.

90th percentile

Sort individual function scores from lowest to highest and take the nearest-rank score at 90% of the count, rounding the rank up. At least 90% of included functions have complexity at or below this score. It highlights the upper end of the distribution and is N/A without functions.

High-complexity function rate

100 * functions above threshold / function count. A function exactly equal to the threshold is not included. The rate is N/A without functions; it is distinct from the fixed 21+ score-colour band.

Change from baseline (%)

100 * (current / baseline - 1). For example, a change from 100 to 120 is +20%, and a change from 100 to 80 is -20%. Zero or missing baseline values have no meaningful percentage: analysis tables show N/A and charts leave gaps rather than inventing a value. Charts space runs by their actual dates.

Built-in exclusions Files matching %eslint-configs/%, %mock%, %test-setup%, %.json, or libs/shared/% are always hidden from visible report statistics. Removing project exclusions does not restore these files.
